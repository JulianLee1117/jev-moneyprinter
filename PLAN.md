## Milestone 1: reproducible extraction and event state

Use a small Python command-line package, SQLite for metadata and state, and content-addressed files for raw source bytes and extracted passages. Use typed validation at input/output boundaries. Exact dependencies and compatible versions will be selected at implementation time. A provider adapter permits a stronger-model baseline without changing downstream schemas.

Pipeline: discover documents → archive bytes and metadata → extract text/tables → link cases and prior state → select relevant passages → classify with Jev → validate evidence and numeric fields → produce a local research alert.

Core records:

- **SourceRecord:** canonical URL, source ID, retrieved-at UTC, status, content hash, original bytes path, parser version, stated dates, timestamp evidence and precision.
- **EventEpisode:** stable case/episode ID, linked documents, country/exporter, agency, procedural stage, prior state, action, effective date, candidate evidence spans, novelty classification, ambiguity flags.
- **RateObservation:** rate type, numeric value as decimal, unit, exporter applicability, old/new status and evidence. Keep AD margin, CVD rate and cash-deposit rate separate. Avoid naive addition where offsets apply; distinguish forward deposits from retrospective assessment/refund issues.
- **IssuerExposure:** issuer/security ID, ticker with valid dates, entity/product/geography, exposure role, ownership window and documentary support. Candidate issuer IDs come from this map.
- **ModelRun:** requested and returned model, provider if supplied, schema version, input/question hashes, raw response, usage/cost, start/end times, validation outcome and retries.
- **ResearchAlert:** event ID, evidence links, what changed from prior public state, potentially affected issuers, uncertainty, observed-at time and processing delay. Jev confidence is not the probability of a profitable trade.

Numbers and free-form facts come from deterministic parsers or an independently validated extraction step. Jev evaluates predefined questions/candidates; it must not be expected to generate arbitrary quotes, tickers or company names. Cite original spans by candidate ID and let code resolve them to source text. Model uncertainty can abstain; validators reject unsupported or contradictory critical fields.

Benchmark against structured-field/keyword rules and a stronger model on the same blinded examples. Measure stage/action accuracy, rate/applicability correctness, material-change recall, false alerts, and cost per useful alert. A proposed extraction gate is at least 95% precision for material-change alerts on adjudicated examples, with recall and sample uncertainty reported separately. This is a project hurdle, not an industry standard or evidence of alpha.

## OpenRouter integration contract

- Model request ID: `typesafe/jev-1.13` (no tilde). Avoid the moving `~typesafe/jev-latest` alias in the experiment.
- Route: `POST https://openrouter.ai/api/alpha/decisions`. This is not a normal chat-completions request.

## Jev-specific alpha design requirement

Research requirement: take full advantage of Jev's capabilities for alpha discovery. The implementation must use its shared-state parallel decisions and full probability outputs as a central experimental treatment, not merely as a sentiment classifier or summary generator.

**Novelty boundary:** the current collector and small CORE screen could have been built with earlier language models. Jev's distinctive opportunity is making extensive, typed, probabilistic semantic screening cheaper/faster, not introducing exclusive information or established financial forecasting skill. A small low-volume family may not benefit enough to matter. Do not describe the working foundation as a demonstrated Jev-enabled alpha engine.

In addition to the equal-evidence ablation below, require a **fixed-budget coverage experiment** before claiming Jev enables a worthwhile new strategy. Freeze one candidate universe and ordering, source availability, machine-cost allowance, elapsed-time allowance and reviewer-time allowance. Compare (a) deterministic retrieval/rules, (b) a capable conventional model, (c) Jev screening with explicit deeper-review routing. Include all acquisition, parsing, retry and review costs, not just model tokens. Measure correctly identified distinct economically relevant episodes, recall on adjudicated random samples (including rejects), false-alert load and observed end-to-end delay. A broader classifier result or lower token bill is not an alpha result; holdout post-alert net returns remain a separate gate.

The proposed use of extra coverage is a document × known product/exposure × issuer economic-channel evaluation over a dated, evidence-backed candidate map. Parallel judgments test direct producers, affected importers and verified customers/competitors; code handles dependent stages and numbers. Do not generate thousands of unsupported ticker relationships or treat question/candidate counts as independent financial samples. CORE is the first calibration/rejection fixture. Expand to other registered trade-remedy families only when the exposure/data audit identifies credible opportunities. Do not launch a seven-feed platform to manufacture scale.

TypeSafe's architectural/speed claims motivate this comparison but are not our measurements, especially through OpenRouter. Full probability preservation is implemented; domain calibration, budget-matched coverage gains and improved trading outcomes remain untested. [TypeSafe model design](https://typesafe.ai/blog/introducing-system-one-models-and-jev), [parallel choice outputs](https://docs.typesafe.ai/primitives/choice).

Initial specification: `research/jev-core-question-pack.v1.json` contains **28 typed questions** spanning authority, proceeding, finality, comparability, novelty, rate applicability, forward versus retrospective treatment, scope, timing, import competition, contradictions and separate NUE/STLD economic channels. It is a design artifact awaiting labeled evaluation, not a validated trading signal or a directly executable full API request.

Use a staged architecture:

1. **High-recall evidence selection.** Retrieve broadly from the new document and prior case state. Use batched Jev judgments to classify candidate passages as operative evidence, relevant exception, supporting context, historical quotation or irrelevant material. Preserve source spans and a supporting tier so filtering does not silently remove exceptions. Log recall on human-labeled material.
2. **Shared-state parallel semantic panel.** Supply a compact, identical evidence packet containing current passages, prior publicly known treatment, validated numbers/dates and dated issuer candidates. Evaluate the 28-question panel together where it fits the provider context budget. Keep independent questions within a pass; use code to construct subsequent passes if a question truly depends on an earlier answer.
3. **Company-by-channel expansion.** Generate parallel questions for verified issuer candidates across domestic production, imports/input costs and foreign operations. This is the path to second-order research as coverage expands. Use provided candidate IDs and evidence; do not ask Jev to invent a universe or exposure percentages. Separate irrelevant from unknown exposure.
4. **Uncertainty and contradiction handling.** Store full available answer probabilities rather than only winning labels. Calibrate interpretation, applicability and exposure scores separately on held-out human labels. Contradictions, missing prior state or offset ambiguity trigger review/abstention. Never multiply question probabilities into a supposed trade-win probability. Equivalent prompt variants and document chunking are robustness checks, not independent statistical votes.
5. **Semantic state changes.** Maintain a versioned case history and compare each announcement to its prior public state. Changed legal treatment and surprise relative to market expectations are distinct fields. Market expectations stay unknown unless independently supported. Code computes numeric rate deltas and date comparisons; Jev evaluates whether passages and applicability justify that comparison.
6. **Information-gain routing.** Reserve deeper model/human work for cases with substantive new evidence, credible exposure or unresolved material ambiguity. Do not discard every low-confidence case: ambiguity can be economically important. Keep a sampled audit of rejected candidates to estimate missed opportunities.

The full panel becomes an auditable semantic dataset. Initial return analysis uses only a few prespecified aggregate concepts—substantive change, conditional economic direction and supported issuer exposure—rather than fitting 28 coefficients to a handful of events. The two issuer reactions, country rows, document chunks and questions associated with one announcement are dependent observations from that episode.

Required ablation, using the **same documents, prior-state evidence, exposure map and entry timing**:

- A: structured fields and deterministic rules.
- B: A plus one simple event classification.
- C: A plus the full Jev semantic panel.
- D: the same panel evaluated by a stronger model, first on the extraction benchmark.

Compare correct material-change detection, missed events, false alerts, inference cost and analyst effort before evaluating incremental post-alert return information. Jev's advantage is established only if C adds useful discrimination or coverage beyond A/B, at acceptable cost, and any trading contribution survives a frozen return test. More questions alone are not evidence of more alpha.

## Milestone 2: market-data decision and event study

The user has no paid intraday feed. Milestones 0–1 work with public documents and do not require one. EOD data can support a limited daily diagnostic, but cannot establish an intraday opportunity or an executable entry price. Do not silently substitute a daily close for a quote available at the alert time.

After timestamp and event-count gates pass, compare providers for a small event-window purchase: historical coverage, adjusted/unadjusted prices, corporate actions, exchange timestamps, bid/ask availability, use rights and total quote. Choose the minimum adequate dataset. No subscription is assumed or purchased by this plan.

Before looking at outcome returns, freeze:

1. Event inclusion, episode grouping, exposure map and signed hypotheses. Primary universe NUE/STLD; mixed CLF exposure is separate.
2. Primary horizon: entry at the first eligible regular-session executable quote at least 15 minutes after the event is usable under the defined latency scenario; exit at the following regular-session close. Calendar, timezone and after-hours handling must be explicit. Shorter/longer horizons are labeled secondary diagnostics.
3. Timestamp policy: historical analysis uses documented availability with an explicit latency assumption; live analysis uses actual receipt plus processing. Use date-only cases only for an explicitly separate conservative daily analysis. First public inspection is not automatically the earliest public disclosure.
4. Baselines: no-information/event-unconditional behavior; keyword/structured-field event rules; Jev-enhanced interpretation. Record broad market/steel-sector movements and contemporaneous earnings/major tariff news. Do not use a steel ETF alone as a perfect unaffected control: it may contain exposed issuers.
5. Costs and execution: spread, slippage, commissions if applicable and data cost allocation. Signals requiring shorts cannot be called implementable without borrow assumptions/data. Report unverified costs and execution constraints.
6. Chronological development/holdout with entire investigation families protected against tuning leakage; multiple countries/stocks from an episode remain clustered. Record all model/schema/threshold experiments. Prefer transparent rules and event studies over fitting a high-dimensional returns model to a small sample.

Report effect sizes, uncertainty, event concentration, sensitivity to feasible delays and costs, and failure cases. Extraction correctness, an announcement-day move and profitable post-alert returns are three different outcomes. Historical source-only extraction reduces but does not eliminate the risk of model hindsight; prospective evaluation remains necessary.
